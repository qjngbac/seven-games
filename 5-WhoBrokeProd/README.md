# 谁动了生产环境 · 多人对话推理

一款网页版**对话侦探 / 证据推理**游戏（类《请出示证件》的职场悬疑）。玩家询问多名角色、比对证词与客观记录，在有限提问次数内重建事件链，并提交结构化指控。

技术栈：**Vue 3 + TypeScript + Vite + Pinia + Vitest**（与系列其他游戏一致）。

## 运行

```bash
npm install          # 或复用同系列 node_modules
npm run dev          # 开发服务器
npm run build        # 产出 dist/
node serve.mjs 5189  # 静态预览（http://127.0.0.1:5189/）
npm test             # 规则层 + 内容可达性测试（87 项）
npm run typecheck    # vue-tsc，零类型错误
```

## 核心玩法

1. **案件档案**：了解目标与已知事实、涉案人员。
2. **调查中心**：询问嫌疑人（消耗提问次数）、直接检视证据与记录（**不消耗提问，永不锁死**）。
3. **对话**：选择话题获得回答；向嫌疑人**出示证据**可逼出与公开说法矛盾的真话，并解锁新话题。
4. **推理板**：把互斥事实连成「矛盾」即可识别谎言；系统会提示未识别的潜在矛盾。
5. **指控**：提交责任人、危险行为、时间、动机与引用的证据 —— 结构化校验，不用字符串关键词。
6. **结算**：真相时间线回放 + 结案评价 + 声誉变化。

## 架构（严格按开发文档 §3/§5/§6）

```
src/
  case-model/         # 纯逻辑层，可脱离界面单测
    types.ts          # 全部数据模型类型
    truth-graph.ts    # 客观真相图：查询 / 时间线 / 矛盾计算 / 可达性校验
    knowledge.ts      # 角色有限视角（所知 / 所信 / 意图）
    conditions.ts     # 回答/话题解锁条件匹配
    claim-validator.ts# 结构化指控校验（事实集 / 证据集 / 禁止矛盾 / 等价表述）
  dialogue/           # 对话引擎
    topic-engine.ts   # 话题解锁
    response-selector.ts # 按条件+证据+关系选最高优先级回答
  evidence/board.ts   # 推理板：节点连接、矛盾/支持识别、提示
  data/cases/         # 内容驱动：7 个案件定义（新增只需追加）
    case1-force-push.ts … case7-cron.ts
  store.ts            # Pinia 状态机（CASE_SELECT→BRIEFING→INVESTIGATION↔DIALOGUE↔BOARD→ACCUSATION→VALIDATE→RESULT）+ 事务式存档
  components/         # 7 个界面组件 + 设置面板
```

### 设计支柱（文档 §1.1）

- 角色只知有限视角，回答≠作者旁白。
- 谎言 / 误解 / 记错 / 隐瞒严格区分（`intent`）。
- 证据有来源与可信度，关键证据（日志、记录）**直接可检视**，不会因提问顺序被永久错过。
- 最终指控提交完整事件链，多责任人可分别指认。

## 防 bug 保证（内容测试）

`src/data/content.spec.ts` 对每个案件自动校验（共 72 项内容断言 + 15 项单测/对话 = 87 项全绿）：

- 每个被引用的关键事实都有获得路径（证据或证词）— 无不可达事实。
- 每个话题都有无条件兜底回答 — 不会出现死局 / 无选项。
- **仅检视证据即可拿到全部 requiredFacts** — 关键证据永不被锁死（无永久锁死）。
- **存在一条完成路径**：模拟"完整调查"后正确指控必为 `success`。
- 矛盾对双方均可被发现 — 推理板能识别谎言。
- 责任人 / 管理责任 / requiredEvidence 均为真实实体。
