# 荒诞审查局 · 多场景版（AbsurdCensor）

规则核对 / 文件审查 / 时间管理 / 叙事 类网页游戏。玩家依据每天变化的规则审查人物与文件，在**效率、准确、道德、组织压力**之间做决定。类《请出示证件》但荒诞风：制度是真的，例外也是真的。

技术栈：Vue 3 + TypeScript + Vite + Pinia + Vitest（设计文档首选 Godot，但明确给出 Vue3 卡片式替代路线，与系列 1/2/3/7 一致）。

## 运行

```bash
npm install        # 若未复制 node_modules
npm run dev        # 开发模式 http://127.0.0.1:5188
npm run build      # 产出 dist
npm run serve      # 静态预览已构建成品（端口 5188）
npm test           # 运行 26 个单元测试（含全场景意图一致性校验）
```

> 不能直接双击 `dist/index.html`——Vite 产物走 ES module，必须经本地服务器（预览/serve）。

## 玩法

1. **首页**：选择要进入的审查场景。
2. **晨报**：看当天规则（每天新增 1-2 条，黄色高亮为新增）、新闻、配额。
3. **工作台**：左看申请者（人像/陈述/携带物/道德提示），中看文件（点「核验真伪」查证据），右看规则书。
4. **盖章**：放行(A) / 暂扣(S) / 拒绝(D)。裁定后即时揭示合法与否、违反/例外条款、真相。
5. **日结**：准确率、工资、罚款、组织压力、良心值、剧情消息。
6. **结局**：场景最后一天（或组织压力爆表被停职）按累计状态给出 7 种结局之一。

## 核心架构原则（务必遵守）

- **规则是唯一事实来源**：合法性由 `RuleEvaluator` 用结构化规则 DSL 计算，绝不写死。错误靠**字段逻辑差异**（姓名/机构/电量/有效期/一致性/数值阈值）而非像素级刁难。
- **默认放行 + 优先级评估**（设计文档 6.4）：`active = rules.filter(matchesContext).sort(priority asc); result = {allow:true, deny:false}; for rule: result = rule.apply(...)`。违规设 `deny`，`allowIf` 例外（最高优先级）覆盖一切拒绝。
- **合法 ≠ 道德**：`RuleEvaluator` 只判制度正确性；`NarrativeEngine` 单独处理剧情后果与多结局，两者不混。
- **数据驱动**：场景在 `src/data/scenes.ts`（4 个场景、17 个工作日），申请者在 `src/data/cases.ts`（约 120 名，含 `intent` 自校验）。每人的合法裁决由引擎**反向验证**（`buildCase` 调 `evaluate`），测试批量复核。

## 内容规模

- **4 个场景 / 17 个工作日**，规则逐日叠加。
- **约 120 名申请者**，覆盖全部规则组合与边界：过期证、姓名冒用、野鸡机构、低电机器人、违禁品、灰区来客、外交官、游客、宵禁夜归、发烧客、超量液体/现金、信用不足、基因冒名、无记忆备份机器人、未注册义体，以及各场景的「签名例外」——猫/急救车/机组/市长能覆盖一切违规，是游戏的荒诞核心。
- 规则类型：`requireDocument / requireField / fieldMatch / fieldInList / notExpired / allowIf / denyIf / forbidDocument`（后两者支持 `when` 条件上下文）。
- 道德冲突：灰区母亲、低电机器人、迷路游客、夜归人、发烧客等案例，合法但冷血 vs 顺良心的抉择会影响结局。

## 测试（26 passed）

- 规则引擎：默认放行模型、猫/急救车/机组/市长例外覆盖违规、各场景关键违规正确判定。
- 字段逻辑：姓名不一致/过期/电量不足/机构不合规/违禁品/灰区/无预约游客/外交免检/液体超量/信用不足/基因不符 各自正确判定。
- **内容意图一致性（全场景）**：全部约 120 名申请者的 `intent` 与引擎计算结果逐一一致；每天案件数满足配额；暂扣永远合法；各场景签名例外确实生效。
- 可解性批量校验：每名申请者至少一个合法裁决，且 `expected` 与引擎一致（设计文档 5.2）。
