# 今天别把机房炸了 · 错误操作模拟器

故障诊断 / 操作顺序 / 轻模拟网页游戏。玩家在时间、工具和客户压力下诊断设备故障，
选择正确操作顺序，并承担错误操作的连锁后果。

技术栈：**Vue 3 + TypeScript + Vite + Pinia + Vitest**（按设计文档的“替代路线：Vue 3 卡片式操作流”实现）。

## 玩法
- 接收工单 → 简报 → 现场（设备拓扑 + 状态灯 + 工具栏 + 日志 + 时间/预算 HUD）→ 检查/操作（高危二次确认）→ 提交验收 → 结算复盘。
- **设备状态是唯一事实来源**：症状由底层状态推导，操作只修改声明的状态，依赖变化按确定顺序传播。
- 同一症状可对应不同根因（如“离线”可能是交换机断电，也可能是本机网口松）。
- 高危不可逆操作（恢复出厂 / 格式化录像盘 / 破拆）需二次确认，会产生损失。
- 结算评分：正确性 / 损失 / 用时 / 满意度 / 离谱度；复盘回放操作时间线并标记第一次偏离参考解法的位置。

## 运行
```bash
npm install          # 首次（或复制 2-ImpostorLies 的 node_modules）
npm run dev          # 开发模式 http://localhost:5187
npm run build        # 类型检查 + 生产构建到 dist/
npm run preview      # 预览已构建成品
npm run serve        # 静态服务 dist（端口 5187）
npm test             # 运行 78 个单元测试
```

## 内容规模
- 设备 15 类 / 23 个实例：交换机 / 摄像头×4（每路故障各不相同）/ 录像机 / 服务器（风扇·内存·网卡·磁盘）/ 门禁 / 打印机 / 台式机×2 / 智能感应门 / 网线（主干+每路各一，共 5 根）/ **市电配电箱** / **UPS 不间断电源** / **机房空调** / **网关路由器** / **无线 AP** / **光纤收发模块**。
- 动作 48 个（检查 / 修复 / 重启 / 高危），含跨设备依赖与前置条件；含供电主干、空调、网关、AP、光纤的诊断与修复工具箱。**每种动作都有可用场景**（由 `controller.spec.ts` 的"无死数据"测试保证）。
- 工单 43 个，难度分 7 章：
  - 第一章 单故障入门（含台式机/感应门首秀）
  - 第二章 多设备·网线（断裂/主干被剪）·服务器网络
  - 第三章 错误客户描述·并发·摄像头差异化（IP 冲突/失焦）·蓝屏
  - 第四章 荒诞并发·**四路摄像头四种不同故障**·感应门双重
  - 第五章 综合多机（网线+台式机+感应门 / 服务器+台式机）
  - **第六章 一环扣一环（连环故障）**：空调停机→服务器过热 / 市电跳闸+UPS 电池耗尽→全楼断电 / 网关配置丢失→外网+AP 双掉 / 交换机松连带 WiFi / 光纤被啃→主干断 / 空调+网卡双因 / 全楼断电连环 / 终极五因综合
  - **第七章 工具箱补齐**：AP 掉线 / 台式机断电·显示器损坏·系统盘满 / 服务器磁盘满致服务停摆 / 感应门控制器死机·门体卡阻 / 摄像头夜视失效·适配器损坏 / 单路网线接头松 / 市电+UPS 双保险全断
- 每工单均含根因、证据动作、修复动作、可选高危错误操作、验收条件、搞笑反馈与参考解法路径。
- 摄像头难度升级：每路根因各异（网口松 / 镜头挡 / 配置丢 / 适配器坏 / IP 冲突 / 红外坏 / 进水 / 失焦），工具箱步骤对应增多。
- **连环故障机制**：设备状态是唯一事实来源，新增依赖链——供电主干（市电/UPS）决定交换机/服务器/NVR 是否断电；机房空调停机会使服务器过热；网关配置丢失会同时拉掉服务器外网与无线 AP；交换机断电会连带无线 AP 掉线；光纤模块损坏会让主干链路断；服务器磁盘写满会拖垮关键服务。症状由状态推导，场景洞察会提示“多设备同时断电→查市电/UPS”“服务器过热但风扇正常→查空调”“外网断→查网关”。

## 测试（78 passed）
- 每关参考解法满足验收且不违反约束（可解性，含全部 43 关），且参考解法不造成任何不可逆损失。
- 依赖传播（交换机断电 → 四路摄像头同时离线 → 复电恢复）。
- **网线链路依赖**：主干被剪 → 交换机仍亮但四路全离线；单路断裂只影响该路。
- **连环故障依赖**：市电跳闸+UPS电池耗尽 → 交换机/服务器/NVR 全断电；空调停机 → 服务器过热；网关配置丢失 → 服务器外网+AP 双掉；交换机断电 → AP 掉；光纤损坏 → 主干断；服务器磁盘满 → 关键服务停摆。
- 症状由状态推导（在线但镜头遮挡/失焦 ≠ 离线）。
- 台式机（内存/显示器/蓝屏/磁盘/插头）、智能感应门（传感器脏+错位/控制器/卡阻）、服务器网络（网卡）可解性。
- 摄像头四路差异化：A 网口松 / B 遮挡 / C IP 冲突 / D 进水，参考解法全满足。
- 操作前置条件不可绕过；高危操作标记 highRisk 且产生损失。
- **不可逆损失必须进入结算**：先"恢复出厂"毁配置再修好原故障，验收虽通过但评价封顶 C，且结局标题如实披露（不会误判为"根因已消除"）；`noFactoryReset` 覆盖全部高危不可逆动作（含破拆）。
- **内容完整性**：每个已定义故障都至少被一个工单注入；工单引用的动作/故障/设备均存在；参考路径动作都在 `availableActions` 内。
- 约束违反触发失败；临时修好（静音告警）满足验收但根因未除。
- 场景洞察：交换机正常但多摄离线 → 提示逐根排查网线；多设备同时断电 → 查市电/UPS；服务器过热但风扇正常 → 查空调；外网断 → 查网关。
- 时间线可复现最终状态。
